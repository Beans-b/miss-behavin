How far is each proxy from what a shopper actually sees?

The gap is not the same on every engine, and it decides how much weight a proxy row can carry.

EngineGapWhy
ChatGPT Narrowest chatgpt.com and the OpenAI API share a model family and OpenAI’s own web search. The differences are product-layer: default model, settings, personalisation, memory.
Google AI Mode Wide AI Mode runs query fan-out — one question becomes 8–12 sub-queries, each retrieved and ranked by Google Search. The Gemini API runs a single search with no fan-out. Genuinely different retrieval: only about 35% of URLs cited in AI Mode match Google’s organic top 10, which is machinery the API does not have.
Copilot No proxy at all Not a gap — a substitution. No consumer API exists. The Azure Grounding-with-Bing lane was built and is parked, and it would have been Bing-grounded GPT rather than Copilot: a different product, further out than the other two. Read Copilot manually.

So, weighting the proxy rows: lean on ChatGPT most, Google less, and do not expect a Copilot row at all.

Caveat that matters: that ranking comes from how the systems are built, not from anything measured on these 16 queries. Nobody has yet compared a manual read against a proxy read on this store. The manual sitting is what turns this table from reasoning into evidence — and if the ChatGPT proxy turns out to track the manual read closely, that engine can be trusted to the automated lane and left there.

Why is the manual lane not automated too?

Because the consumer surfaces have no API, and scripting them is off the table. chatgpt.com, Copilot and Google AI Mode publish no interface for reading their answers. The only way to automate them would be to drive the real websites with a bot — and that (a) breaks all three providers’ terms of service, which prohibit automated access to the consumer products, and (b) runs straight into bot detection and CAPTCHAs, so it only works if you build evasion. We are not building that. It would also break every time they change their markup.

The APIs are the sanctioned automated path, and that is exactly what the proxy lane is. It is not a lesser version of the manual lane — it is a different instrument that happens to answer a similar question. See CE-D10 and CE-D12.

The manual lane is a ONE-OFF, not a recurring cost. This is the part worth being clear about: you do 16 queries once, roughly 25 minutes, to find out how far the proxy sits from the real thing. After that the proxy runs quarterly in minutes for pennies, and you only repeat the manual read if you stop trusting it. 25 minutes once buys you an automated instrument you can actually believe. Skip it and you have a fast number nobody can check, which is worse than a slow number you can.

It is also delegable. Nothing about pasting cited URLs needs the person who runs the engagement — it needs incognito, the query list, and care not to re-roll a query you dislike.

Third-party AI-visibility tools do automate the consumer surfaces. They carry the terms-of-service exposure and the scraping infrastructure themselves, and they charge a subscription for it. That is a real option and a real trade — CE-D3 currently rules out paid tooling at this store’s size, and that decision is Brian’s to revisit, not something this tab should quietly work around.
